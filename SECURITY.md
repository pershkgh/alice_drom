# Безопасность

## Как сообщить об уязвимости

**Не открывайте публичный issue.** Используйте приватный канал:

- вкладка **Security → Report a vulnerability** в этом репозитории
  (GitHub Security Advisories — сообщение видно только мейнтейнеру);

Опишите: версию/коммит, шаги воспроизведения, что происходит и чем это опасно.
Ответ — в течение недели, обычно быстрее.

## Как устроена защита вебхука (и почему не «подпись»)

Яндекс **не подписывает** запросы к навыку: в теле приходят только `session.user.user_id`
и `session.skill_id`, и их может указать любой, кто отправит POST. Поэтому проверки
подписи не существует и существовать не может. Защита строится так:

1. **Секретный путь.** Инсталлер генерирует `WEBHOOK_SECRET`, адрес становится
   `https://домен/alice/<секрет>`. На любой другой путь навык отвечает `404`.
2. **`OWNER_USER_ID`.** Опубликованный навык вызывается любым пользователем Алисы,
   поэтому чужим он отказывает.
3. **`API_TOKEN`.** Пульт (`/api/*`) закрыт всегда; если токен пуст — API отвечает
   `503`, а не открывается.

## Что считается уязвимостью

- обход проверки подписи Яндекса на вебхуке `/alice`;
- доступ к `/api/*` без `API_TOKEN`;
- доступ к Music Assistant или Navidrome через навык (SSRF, проксирование чужих адресов);
- чтение `.env` или чужих токенов через API/логи;
- выполнение команд на сервере (RCE) через текст запроса.

## Что не считается

- **Отсутствие подписи вебхука** — не уязвимость сама по себе, это устройство платформы;
  см. выше, как закрывается.
- **Публикация навыка сама по себе** — не уязвимость: без неё Яндекс не запускает
  воспроизведение. Уязвимость — **опубликованный навык без `OWNER_USER_ID`**: тогда
  чужой пользователь Алисы может управлять вашей колонкой. Поэтому после публикации
  ограничение по `user_id` обязательно.
- Слабый пароль/токен, который вы сами поставили.
- Доступ к порту 8100 из вашей локальной сети (он так и задуман — пульт работает в LAN).
- Отсутствие TLS между навыком и Music Assistant внутри одного хоста.

## Что делает проект для безопасности

| Механизм | Где |
|---|---|
| Секретный путь вебхука `/alice/<секрет>` | `skill/app.py`, `WEBHOOK_SECRET` |
| Отказ чужому `user_id` (после публикации) | `skill/app.py`, `OWNER_USER_ID` |
| Проверка `session.skill_id` (опционально) | `skill/app.py`, `SKILL_ID` |
| `/api/*` закрыт всегда; пустой токен = API выключен | `skill/app.py`, `_api_guard` |
| Токен `API_TOKEN` на `/api/*` | `skill/app.py`, `_token_ok` |
| Наружу проброшен только `/alice` | `deploy/Caddyfile` |
| Секреты только в `.env` (600), без логов | `install.sh`, `.env.example` |
| Логин Яндекса не попадает в навык | хранится в Music Assistant |
| Образы собираются из закреплённых версий | `skill/Dockerfile`, `ma-station/Dockerfile` |

## Если токен утёк

1. Новый токен: `openssl rand -hex 24`.
2. Впишите в `.env` (`API_TOKEN=...`).
3. `docker compose up -d --force-recreate`.
4. Обновите токен в приложении (раздел «Настройки»).
