# Тесты без колонки, сервера и домена

Оба набора запускаются где угодно: на своём ноутбуке и в CI. Ничего не трогают —
работают в `mktemp -d`, поднимают контейнер на свободном порту и убирают за собой.

## 1. `install/run.sh` — сухой прогон установщика

```bash
bash tests/install/run.sh
```

Подставляет фиктивные `docker`, `curl`, `dig`, `ss` и отвечает на вопросы установщика так,
как это сделал бы человек. Проверяет: `.env` со всеми ключами, права 600, сгенерированный
`API_TOKEN`, печать вебхука и имени навыка, напоминание про Яндекс.Диалоги, бэкап `.env`
при повторном запуске.

Docker не нужен — 2 секунды.

## 2. `sandbox/run.sh` — навык в контейнере с моком Music Assistant

```bash
bash tests/sandbox/run.sh
```

Что делает:

1. поднимает `sandbox/mock-ma.py` — маленький сервер, который притворяется Music Assistant
   (станция «играет», очередь из 5 треков, обложки по `/imageproxy/…`);
2. собирает реальный образ навыка из `skill/`;
3. запускает контейнер, подставляя `MA_URL` на мок;
4. проходит 30 проверок: `/health`, 401 без токена, `/api/status` (трек, исполнитель,
   длительность, громкость 40 → 4/10), команды «пауза/продолжи/дальше/громкость 3/
   что играет/включи evanescence» и то, что каждая **дошла до MA** нужной командой,
   очередь с обложками, `/api/diagnostics`;
5. убивает мок и проверяет деградацию: `/api/status` отвечает `ok:false`, `/health`
   остаётся 200, команда возвращает внятный текст, а не зависает.

Нужен только Docker и `python3`. Полторы минуты.

Переменные: `MOCK_PORT`, `SKILL_PORT`, `PYTHON`, `WORK` (по умолчанию свободные/временные).

## Что эти тесты не покрывают

- настоящую колонку (Glagol, поток на 8097) — проверяйте на живой станции;
- Яндекс.Диалоги (ping и подпись запросов) — только реальный Яндекс;
- домен, сертификат и Caddy — проверяются `./doctor.sh` на сервере.
