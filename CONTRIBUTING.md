# Как участвовать

Проект домашний: развивается под свои задачи, но пул-реквесты и баг-репорты приветствуются.

## Перед изменениями

- Ошибка: откройте issue с шаблоном «баг» — версия, шаги, что ожидали, что получили,
  вывод `./doctor.sh`.
- Идея крупнее пары строк (новый интент, интеграция, LLM): сначала issue, чтобы
  не переделывать работу дважды.

## Локальная разработка

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r skill/requirements.txt

# навык без Docker (нужны MA_URL и MA_TOKEN в окружении)
cd skill && uvicorn app:app --host 127.0.0.1 --port 8100

# проверка разбора фраз — самое быстрое, на чём можно поймать регрессию
python3 - <<'PY'
import sys; sys.path.insert(0, 'skill')
import intents
print(intents.parse('включи избранное', 'Домашняя музыка'))
PY
```

Windows-пульт:

```bash
cd windows && dotnet build -c Release     # нужен .NET SDK 8+; получится net48 exe
```

## Чего придерживаемся

- **Ответ Алисы ≤ 1–2 предложения.** Это голос, а не экран: длинную реплику не дослушают.
- **Транспорт отвечает молча** (`end_session: true`), иначе навык «приседает» после каждой команды.
- **Никаких секретов в коде и в git.** Всё через `.env`; `API_TOKEN` обязателен на `/api/*`.
- **Навык живёт опубликованным** (в черновике Яндекс не запускает воспроизведение),
  поэтому код обязан защищать владельца: не убирать проверку `OWNER_USER_ID`
  и не добавлять путей, которые её обходят.
- **Диагностика важнее красоты:** любая новая интеграция должна уметь сказать,
  что именно сломано (см. `skill/app.py`, `/api/diagnostics`).
- Комментарии и тексты — по-русски, как и остальной проект.

## Проверки перед PR

```bash
python3 -m compileall -q skill          # синтаксис Python
bash -n install.sh doctor.sh            # синтаксис скриптов
docker compose config > /dev/null        # валидность compose

bash tests/install/run.sh                # установщик без Docker
bash tests/sandbox/run.sh                # навык + мок Music Assistant
```

То же самое гоняет CI — дождитесь зелёного прогона.
